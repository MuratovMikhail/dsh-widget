# История изменений

## 1.0.10 — 2026-11-15

### Исправлено

- `cancel-pending-plugin.ps1` больше не считает нечитаемый профиль DSH отсутствием плагина. Состояние профиля теперь `present`/`absent`/`unknown`, и неизвестное состояние завершает отмену ошибкой, а не успехом. Код возврата `remove-plugin.ps1` пишется в лог и попадает в сообщение об ошибке.
- Отмена останавливает дерево процессов этой установки: `install-plugin.ps1` запускает DSH CLI через `cmd.exe`, и эта команда вместе с дочерним `node.exe` могла завершить установку после того, как родительский PowerShell был убит. Осиротевшие команды установки, в которых остался путь `<app>\plugin`, тоже останавливаются.

### Тесты

- `tools/test-cancel-plugin.ps1` проверяет нечитаемый `package.json`, отложенную установку через `cmd.exe` и осиротевшую команду установки. Все три проверки падают на предыдущей реализации.

## 1.0.9 — 2026-11-15

### Исправлено

- `cancel-pending-plugin.ps1` находит профиль DSH через `Get-DshHome`: портативная и другая нестандартная установка больше не считается очищенной, пока bundle остаётся в профиле.
- `cancel-pending-plugin.ps1` останавливает только скрипты этой папки установки. Одноимённые скрипты из других каталогов и копий виджета продолжают работать.

### Тесты

- Добавлен `tools/test-cancel-plugin.ps1`: нестандартный `DSH_HOME`, обнаружение через запись деинсталлятора, посторонние процессы и снятие маркера отложенной установки. Запускается из lifecycle-теста установщика.

## 1.0.8 — 2026-11-15

### Исправлено

- `set-mode.ps1` теперь считает отсутствие поля `autostart` изменением и не выходит раньше времени. При обновлении конфига 1.0.6 поле `autostart` добавляется согласованно, даже если режим не менялся.
- Lifecycle-тест обновления удаляет `autostart` из старого конфига и проверяет, что установщик восстанавливает его.

## 1.0.7 — 2026-11-15

### Переключение режимов установщика

- Перед каждой установкой установщик отменяет отложенную установку плагина и удаляет уже стоящий bridge. Переход в `startup` или `manual` больше не наследует `plugin` от прошлой установки.
- Отмена удаляет `pending-plugin.json`, `RunOnce`, останавливает процессы `finish-plugin.ps1`/`install-plugin.ps1`/`set-mode.ps1` и откатывает bridge, если он успел установиться в гонке.
- Перед включением `startup`/`manual` установщик проверяет, что bridge действительно отсутствует; иначе установка останавливается, чтобы не оставить два механизма запуска.
- Ярлыки автозапуска и рабочего стола удаляются, если выбранный режим/задача их не предусматривает. `config.autostart` приводится в соответствие режиму.
- Удаление программы теперь отменяет отложенный finisher перед удалением bridge.

### Тесты

- Добавлены последовательные переходы: plugin → startup, startup → manual, manual → plugin, plugin → manual, pending → manual, pending → startup.
- Проверяются config, `autostart`, манифест и пакет bridge, pending-маркер, startup-ярлык и произвольный путь вместе.
- `tools/test-installer.ps1` теперь отказывается работать, если уже есть пользовательская установка, ярлык, запись деинсталлятора или указатель; lifecycle-тесты запускаются только в изолированной Windows/VM.

## 1.0.6 — 2026-11-15

### Аудит установщика

- Bridge теперь находит виджет через `%LOCALAPPDATA%\DSH Widget\install-dir.txt`, поэтому установка в произвольную папку работает. Указатель пишется установщиком в UTF-8 и удаляется при удалении.
- Отложенный finisher проверяет `pending-plugin.json` и больше не перезаписывает режим, который пользователь выбрал во время ожидания. Настройки удаляют маркер при сохранении режима.
- Установка и удаление плагина используют общий `tools/dsh-common.ps1` для поиска DSH home и CLI. Удаление теперь умеет править профиль и удалять пакет напрямую, если CLI нет или он падает.
- `status.ps1`, `VERSION`, `dsh-common.ps1`, `finish-plugin.ps1` и пакет bridge 1.0.1 входят и в portable-архив, и в EXE.
- Версия читается из `VERSION`; release workflow больше не дублирует её. Тест установщика берёт ожидаемую версию из `VERSION`.
- Тесты установщика проверяют plugin/startup/manual, произвольный путь, обновление, удаление, повторную установку и установку до первого запуска DSH. CI собирает установщик и запускает lifecycle-тест.

### Исправлено

- Настройки больше не теряют режим «Вместе с DeepSeek Harness» из-за read-only переменной `$HOME`.
- Установщик всегда показывает страницу выбора папки.
- Тихая деинсталляция больше не блокируется вопросом о `config.json`.

## 1.0.5 — 2026-11-15

### Исправлено

- Настройки больше не теряют режим «Вместе с DeepSeek Harness»: `Get-DshHome` использовал read-only автоматическую переменную `$HOME` как переменную цикла и возвращал профиль пользователя вместо найденного DSH home.
- Установщик теперь всегда показывает страницу выбора папки; путь по умолчанию прежний — `%LOCALAPPDATA%\Programs\DSH Widget`.
- Первая установка до первого запуска DSH больше не превращается молча в manual. Фоновый finisher ждёт появления профиля DSH, ставит bridge после закрытия DSH и переключает `launchMode` в `plugin`. После перезагрузки попытка повторяется через `RunOnce`.

### Проверено

- Чистый профиль: установщик завершается с кодом 0, виджет установлен, затем finisher ставит bridge после появления профиля.
- Существующий профиль: плагин ставится сразу.
- В настройках появляется режим «вместе с DSH», когда bridge есть.

## 1.0.4 — 2026-11-15

### Исправлено

- Падающий CLI `dsh` больше не прерывает установку плагина до direct-fallback: stderr считается выводом, а не фатальной ошибкой PowerShell.
- Поиск DSH home теперь учитывает записи Uninstall, поэтому портативная установка с профилем рядом с exe находится, если `InstallLocation` зарегистрирован.
- Сообщения об ошибке плагина больше не блокируют `/VERYSILENT`: они пишутся в лог установки, а не показываются модальным окном.

### Проверено

- Локальная матрица: свой `DSH_HOME`, обычный профиль, отсутствие профиля, уже установленный плагин, manual-режим, портативный профиль через реестр, битый профиль. Все коды выхода установщика 0, `launchMode` совпадает с фактическим наличием bundle.

## 1.0.3 — 2026-11-14

### Исправлено

- Установщик записывает `launchMode=plugin` только после того, как плагин-мостик реально появился в профиле DSH. Если плагин поставить не удалось, режим откатывается на manual, а не оставляет `config.json` и профиль в разных состояниях.
- DSH ищется через запущенный процесс, реестр Uninstall, `PATH`, `DSH_HOME` и `%USERPROFILE%\.dsh`, а не только в `%LOCALAPPDATA%\Programs`.
- «Открыть DeepSeek Harness» и проверка плагина в настройках используют тот же поиск, поэтому портативный DSH из папки открывается и определяется корректно.

## 1.0.2 — 2026-11-14

### Исправлено

- Установщик теперь находит CLI DSH в портативной/нестандартной установке и умеет ставить плагин-мостик напрямую в профиль DSH. Это убирает ложное «DeepSeek Harness ещё ни разу не открывали», когда DSH запущен из папки.
- Прямая установка плагина больше не зависит от CLI в `%LOCALAPPDATA%\Programs\DeepSeek Harness`.

## 1.0.1 — 2026-11-14

### Исправлено

- Установщик больше не падает с `Unknown constant 'userprofile'`, если Node из DSH находится только в `%USERPROFILE%`, а не в `%LOCALAPPDATA%`.
- Plan mode теперь показывается в виджете как **«Ждёт подтверждения»**, а не «Работает», пока DSH ждёт «Утвердить» или «Запросить изменения».

### Изменено

- Иконка трея — одна статичная фирменная «D»; состояние показывается в подсказке.
- Убраны дублирующий контактный лист состояний и tray-скрины с русскими надписями из английского README.
- Почищены README, политика конфиденциальности и заметки по Windows 10; удалён неиспользуемый скриншот пустого состояния.

## 1.0.0 — 2026-11-14

### Виджет

- Новый компактный вид: 328×92 px на одну сессию (было 114), без полосы «прогресса».
- Вместо полосы — один индикатор состояния: акцентный спиннер у работы, фиолетовый — у субагентов,
  пульсирующая точка у ожидания, зелёная точка с ореолом у «Готово», красная — у ошибки.
- Спиннер и название сессии окрашиваются в системный акцент Windows (с поправкой на читаемость);
  настройка «Спиннер и название в цвете акцента Windows».
- В шапке — проект (`DSH · billing-service`) вместо `DEEPSEEK HARNESS`; у баланса убрана подпись источника.
- Убраны «шаг 12», «после инструмента», дубли счётчика субагентов, подсказка «двойной клик — DSH»
  и подвал «сессий: N» (вместо него — «ещё N сессий» только при переполнении).
- Прогресс плана — компактный чип `2/5`; время — только там, где оно полезно (`4:32`, `за 3:12`).
- В ожидании показывается текст вопроса агента, а подтверждение (`approval`) — отдельным состоянием
  «Ждёт подтверждения».
- Ход с ошибкой больше не выдаётся за «Готово»: «Остановлено», красная точка с ореолом, системный звук ошибки.
- Ошибка не скрывается автоматически из-за того, что окно DSH было в фокусе: виджет держит её до клика
  по блоку (явное «увидел») или до истечения `doneVisibleSec`.
- Настройки переписаны человеческим языком: «Запуск», «Окно», «Виджет», «Баланс DeepSeek»;
  недоступный без плагина режим не показывается серым огрызком, поле ключа появляется только для своего ключа,
  цифры выровнены по центру, системные белые стрелки заменены аккуратными.
- В меню трея добавлен «О программе»: версия, автор (Муратов Михаил), описание, лицензия и ссылка на GitHub;
  окно использует текущую светлую/тёмную тему, закрывается крестиком или Esc, без отдельной кнопки.
- Шестерёнка настроек перерисована: стандартная иконка Windows вместо похожей на звезду.
- Клик по блоку фокусирует отдельное окно сессии DSH, если оно открыто; переключение вкладки внутри
  основного окна DSH виджет не может — внешнего API для этого нет.
- Добавлены языки: английский (основной), русский и упрощённый китайский; язык следует за Windows,
  переключается в настройках и применяется после перезапуска виджета. Локализованы виджет, трей,
  настройки, «О программе», плагин и README со скриншотами.
- Поддержка Windows 10 (1809+, x64): в Windows 11 используются скругления DWM, в Windows 10 — запасной
  путь через скруглённый регион окна; Segoe UI и Segoe MDL2 Assets заменяют Segoe UI Variable;
  минимальная версия установщика — 10.0.17763.
- Публикация на GitHub: workflow по тегу собирает portable-zip, установщик и SHA-256-контрольные суммы;
  добавлены CI, шаблоны issue, политика безопасности и правила участия.
- Версия для публикации на GitHub — 1.0.0.
- Убрана кнопка проверки звука — режимы «тук-тук»/системный/без звука и так понятны.

### Движок

- Инкрементальное чтение журналов: читаются только новые байты, а не весь файл (8.8 МБ → < 5 мс на обновление
  вместо ~560 мс полного прохода).
- `activeCount` для «ещё N сессий», `todo/write`, сверка `callId` у результатов, `remainder` для записей
  на границе zstd-фреймов.
- Закрыта CORS-дыра: запросы с `Origin` и чужим `Host` получают 403; ACAO больше не отдаётся.
- Движок завершается вместе с UI (`--parent-pid`), чистит устаревшие записи `store`.
- Тик опроса — 1 с; версия отдаётся в `/health` и `/status`; понятная ошибка, если Node не умеет zstd.

### Прочее

- `widget.log` ротируется после 256 КБ.
- Удалён неиспользуемый режим «свой звук» (в UI его не было): остаются встроенный «тук-тук»,
  системный сигнал и «без звука».
- Обновлены превью, README, установщик 1.0.0, лицензия MIT и CI.
- Исправлены мелочи: `install.ps1` больше не копирует неиспользуемый `widget.ico`, в `installer.iss`
  объединены два одинаковых блока удаления, плагин-мостик верно описывает `DSH_WIDGET_DIR`.
